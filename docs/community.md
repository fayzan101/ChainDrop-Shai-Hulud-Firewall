# Community and discoverability

Stars and reach come from a **runnable defensive tool** and an honest research story. They do not come from empty scaffolding, bought stars, or spam.

Track the checklist on GitHub: [issue #14](https://github.com/fayzan101/ChainDrop-Shai-Hulud-Firewall/issues/14).

## What already helps

- Public repo with a clear README (Shai-Hulud / ChainDrop / npm CI in the first screen)
- GitHub **topics** (`npm`, `supply-chain-security`, `github-actions`, `rag`, …)
- Labeled issues so contributors can find Phase 1 and `good first issue` work
- CI badge so visitors see the repo is alive

## When to ask the internet to look

Wait until **Phase 4** (GitHub Action) can allow a benign fixture and fail a synthetic suspicious one. Then:

1. 30–60s demo (GIF or video) — no live malware
2. One technical write-up linking architecture + held-out evaluation question
3. Share once in a place that matches the audience (security engineering, supply-chain, academic showcase)
4. Submit to an awesome-list **only** after the Action is usable

## What not to do

- Buy stars or join star-exchange groups
- Mass-mention people or spam Discords
- Publish worm samples “for virality”
- Pretend the research result exists before Phase 8
